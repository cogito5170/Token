# ga Console — 제품 사양 초안 (2026-10-05)

사용자 결정: 아이디어 A(AI 개발팀 운영 콘솔). 요구: 결과 시각화, 컨설팅 기능(예상 토큰 소모량, 토큰 절약 방법, 개인 맞춤형 서비스)과 추가 기능. 이 초안은 baseline 이 그 요구로 쓴 것이다. 사용자가 고치면 이 파일을 바꾼다.

## 0. ga-sdk 와의 관계 (사용자 확인 2026-10-05)

ga-sdk 를 바꾸는 프로젝트가 아니다. ga-sdk 를 **활용해서** 토큰 서비스 플랫폼을 개발한다.

- **개발 방법으로 활용:** 이 플랫폼은 ga-sdk 0.6 의 동적 노드 풀(`ga work add` → 역할별 노드)과 `ga judge` 로 병렬 개발한다.
- **부품으로 활용:** 이미 검증된 부품을 고정 버전 의존성으로 가져다 쓴다.
  - l0-telemetry: 공급자별 usage 정규화(anthropic · openai · gemini · otel)
  - rlo: Claude Code · Codex · Gemini 기록 읽기, 문맥 예산, 토큰 추정
  - ga: 라우터 통계, FINAL_TASK 실측 데이터
- **ga-sdk 코드는 이 저장소에서 고치지 않는다.** 부족한 점이 생기면 baseline 에 요청으로 올리고, ga-sdk 쪽 작업으로 따로 처리한다.

## 1. 한 줄 정의

사용자의 AI 사용 기록(Claude Code · API · 에이전트 실행)을 모아, 토큰 · 비용 · 품질을 보여 준다. 다음 작업을 더 싸고 정확하게 하는 방법을 데이터로 컨설팅하는 **토큰 서비스 플랫폼**이다.

핵심 질문: "내 AI 작업에 토큰이 어디서 얼마나 들고, 무엇을 바꾸면 얼마나 아끼는가?"

## 2. 핵심 사용자 흐름

1. 가입하고 워크스페이스를 만든다.
2. 사용 기록을 연결한다. 기록 파일 업로드(Claude Code transcript · CSV · JSON), 공급자 usage 내보내기, OpenTelemetry, ga L0 를 받는다.
3. 플랫폼이 기록을 하나의 사용 모델로 정규화한다. 호출 · 세션 · 작업 · 모델 · 캐시 · 비용 단위다.
4. **대시보드와 시각화**로 현재 상태를 본다.
5. **사후 컨설팅**을 받는다. 어디서 토큰이 샜는지, 무엇을 바꾸면 얼마를 아끼는지 알려 준다.
6. 새 작업 전에 **견적**을 받는다. 예상 토큰 · 비용 · 시간 · 성공 확률을 범위로 보여 주고, 추천 구성(모델 · 구조 · 문맥 상한)을 낸다.
7. 제안을 골라 적용한다. 설정 · 템플릿을 내보내며, 사용자 확인 뒤에만 바뀐다.
8. 다음 기록이 들어오면 절감 효과를 재고, 개인 맞춤 모델이 갱신된다.
9. (선택, MVP 이후) 플랫폼 안에서 ga 실행기로 작업을 최적 구성으로 돌린다.

### 3.1 라이브 워크플로 모니터 (사용자 추가 요청 2026-10-05)

AI 노드들이 나눠서 개발하는 모습을 실시간 UI로 보여 준다. 워크플로 모니터링용이다. 오픈소스 데스크톱 에이전트 앱처럼 "일하는 모습"이 보여야 한다.

| 화면 요소 | 보여 주는 것 | 데이터 출처 (ga-sdk 를 고치지 않고 읽는 것) |
|---|---|---|
| 노드 카드 | 노드마다 역할 · 맡은 작업 · 상태(대기 · 턴 실행 중 · 동료 대기 · 판정 중 · 은퇴) · 경과 시간 · 이번 작업 토큰 | `.ga/pool.json`, `.ga/nodes/<n>/run.json`, L0 `node.started` / `node.retired` / `run.end` |
| 작업 보드 | 대기 → 실행 → 판정 → 완료/실패 칸반, 노드가 제안한 하위 작업 표시 | `.ga/queue/`, L0 `work.accepted` / `work.dropped` / `work.failed` |
| 메시지 흐름 | 노드 사이 메시지를 화살표 애니메이션으로, π 가중치는 선 굵기로 | L0 `peer.message.sent` / `received`, `pi.json` |
| 토큰 미터 | 노드별 · 전체 토큰과 비용이 올라가는 게이지, 예산 대비 | L0 `run.end` usage |
| 판정 패널 | 작업별 시험 · 변이 결과, 원래 있던 실패 표시 | verdict/1 |
| 타임라인 재생 | 지난 실행을 시간축으로 다시 재생 | 위 기록 전체(append-only) |

- **형태:**
  - 웹 화면(Next.js)이 기본이다. 같은 컴포넌트를 데스크톱 앱(Electron 또는 Tauri — ADR로 결정)으로 감싼다.
  - 데스크톱 앱은 로컬 `.ga` 디렉터리를 직접 읽어, 서버 없이도 실시간으로 볼 수 있다.
- **ga-sdk 와의 관계:** 모니터는 ga 가 남기는 파일과 L0 기록을 **읽기만** 한다. 노드를 멈추거나 바꾸는 조작은 없다(조작은 나중, 승인 게이트 뒤).
- **현재 ga 기록의 한계:**
  - 턴이 끝날 때만 기록되므로(`run.end`), 턴 진행 중의 세부 활동은 보이지 않는다(어떤 파일을 읽는지, 어떤 도구를 쓰는지).
  - 턴 시작 시각도 따로 기록되지 않는다.
  - 이 부분을 보이게 하려면 ga-sdk 쪽에 `turn.started` 와 턴 진행 이벤트(stream-json 중계)를 추가해야 한다. 이는 이 저장소가 아니라 ga-sdk 작업으로 baseline 에 요청한다.
  - 그 전까지 모니터는 "턴 실행 중(경과 시간)"으로 표시한다.

모든 숫자에 출처를 단다: MEASURED(공급자 usage · CLI 비용), CALCULATED, ESTIMATED(견적), SIMULATED(가정 시뮬레이션). 쿼터는 두 기준(API 정가 환산, CLI 자체 비용)을 나란히 보여 준다(FINAL_TASK 교훈).

## 4. 컨설팅 기능

### 4.1 실행 전 견적 (예상 토큰 소모량)

- 입력: 작업 설명, 저장소 크기 · 언어, 작업 종류(기능 추가 · 버그 · 리팩터 · 문서), 선택한 모델 · 구조 · 문맥 상한.
- 출력: 예상 토큰(입력 · 캐시 · 출력), 비용(두 기준), 호출 수, 시간, 성공 확률. 모두 범위(P10–P50–P90)와 근거(비슷한 과거 작업 N건)로 낸다.
- 처음에는 FINAL_TASK 측정치와 ga 라우터 학습값으로 시작하고, 사용자 데이터가 쌓이면 사용자별로 보정한다.
- 정확도를 스스로 잰다: 실행 후 실제값과 비교해 오차(MAPE)를 화면에 보여 준다.

### 4.2 토큰 절약 진단 (사후)

텔레메트리에서 낭비 패턴을 규칙으로 찾고, 각 패턴에 예상 절감액과 적용 방법을 붙인다. 시작 규칙:

| 패턴 | 감지 기준 (예) | 제안 |
|---|---|---|
| 대량 주입 | 호출당 입력 > 5만 토큰 | 문맥 상한 · 선택 주입(ctxpack) — 측정상 25–63배 차이 |
| 다시 읽기 | 같은 내용이 한 실행에 2회 이상 · 장기 세션 문맥 증가 | fresh 모드, State 재사용 |
| 캐시 미스 | 반복 프롬프트인데 cache_read 0 | 프롬프트 앞부분 고정, 모델별 최소 캐시 길이 |
| 모델 과잉 | 쉬운 작업에 상위 모델, 첫 시도 성공률 높음 | 라우터 단계 낮추기 |
| 모델 과소 | 하위 모델 재시도 · 실패 반복 | 한 단계 올리기 |
| 실행기 오버헤드 | CLI 비용 / usage 비율 높음 | bare 호출, 호출 묶기 |
| 판정 낭비 | LLM 이 판정 · 기계적 검사 | ga judge 로 옮기기 |

제안은 Proposal 이다. 설정 변경은 사용자 확인 뒤에만 일어난다.

### 4.3 개인 맞춤형 서비스

- 프로필: 예산(월 · 작업당), 품질 기준(정답률 하한), 선호 모델 · 공급자, 구독 / API 과금 방식, 팀 규모.
- 사용자별 라우터 · 견적 모델: 이 사용자의 저장소 · 작업 종류에서 맞힌 작업당 토큰을 학습한다.
- 맞춤 추천: "당신의 작업은 X 구성이 맞힌 작업당 Y% 싸다"를 근거와 함께 보여 준다.
- 주간 리포트: 사용량 · 절감액 · 다음 주 권장 설정(문서 · PDF 내보내기).

### 4.4 가정 시뮬레이터 (What-if)

"모델을 Haiku 로 바꾸면?", "문맥 상한을 2만으로 하면?", "노드를 5개로 하면?" → 과거 데이터로 토큰 · 비용 · 정답률 변화를 범위로 보여 준다. 결과에 가정과 데이터 기준을 표시한다.

## 5. 추가 기능

- 예산 가드: 작업 · 일 · 월 상한, 도달 전 경보, 상한에서 자동 정지(체크포인트 후 이어가기).
- 승인 게이트: 정해 둔 행동(push, 의존성 변경, 비용 큰 실행)은 사람 승인 뒤에만.
- 감사 로그: 누가 언제 무엇을 승인 · 실행했는지.
- 다중 공급자: Claude · GPT · Gemini(ga 백엔드 플러그인), 공급자별 비교.
- 팀 워크스페이스: 역할(관리자 · 개발자 · 열람자), 프로젝트별 권한.
- 연동: GitHub(저장소 · 이슈 · 브랜치), Slack/이메일 알림, 내보내기(CSV · JSON), 공개 API.
- 벤치마크: 내 작업을 표준 과제 묶음(FINAL_TASK 형식)으로 재 보는 기능.

## 6. 설계 원칙

1. AI 는 결정권자가 아니다. 노드의 제안 · 컨설팅 제안 모두 Proposal → 정책 → 예산 → 사용자 확인 → 실행.
2. 측정과 추정을 섞지 않는다. MEASURED / ESTIMATED / SIMULATED 를 화면과 API 에 표시한다.
3. 판정은 결정적으로. 시험 · 변이 · 계약 검사는 코드가 하고, LLM 은 판단이 필요한 항목만.
4. 키는 사용자 소유. 콘솔은 공급자 키를 암호화해 보관하거나 사용자 실행기를 쓰며, 로그 · 화면에 키가 나오지 않는다.
5. ga-sdk 를 바꾸지도, 다시 만들지도 않는다. 고정 버전 의존성으로 가져다 쓰고, 플랫폼은 그 위의 제품 층이다.
6. 사용 기록은 사용자 데이터다. 프롬프트 · 코드 본문은 기본적으로 저장하지 않고 토큰 · 메타데이터만 남긴다(본문 보관은 사용자 선택). 업로드 기록에서 키 · 비밀값 패턴을 지운다.

## 7.1 개발 방법 (ga-sdk 활용)

- 0 단계: 아키텍처 세션 하나가 /docs 와 작업 목록을 확정한다(CMD-GC0).
- 1 단계: 작업 목록을 `ga work add` 로 넣고, ga 0.6 노드 풀(동시 3)이 역할별로 개발한다. 역할은 frontend · core-backend · ingestion-analytics · consulting · infra 다.
- 각 작업은 `ga judge` 로 판정한다. 시험 · 변이 · 파일 소유표 검사를 한다.

## 8. 기술 방향 (기본값, ADR 로 바꿀 수 있음)

- Modular monolith: Python 3.12 + FastAPI. ga-sdk 0.6 을 라이브러리로 사용.
- PostgreSQL. 시계열은 우선 일반 테이블 + 인덱스, 필요하면 TimescaleDB.
- 수집: 업로드 · 가져오기 작업은 큐 + 워커. 공급자별 파서는 l0-telemetry · rlo 의 것을 쓴다.
- Frontend: Next.js(TypeScript) + 차트 라이브러리(ECharts 또는 Recharts), 실시간은 SSE.
- 도메인: Identity, Workspace, Source(연결 · 업로드), Ingestion, Usage(정규화 모델), Quota, Estimation, Advisor, Simulation, Profile, Report, Notification, Audit, Integration, (나중) Run.
