# UI 디자인 계약

frontend 는 이 문서와 `design/tokens.json` · `design/encoding.json` · `design/motion.md` 를 보고 만든다. 시각 언어 · 토큰 · 움직임 규칙은 **design** 역할이 소유하고, frontend 는 구현한다(사양 3.1.1, 7.1). 와이어프레임은 `docs/ui/wireframes.md`.

## 1. 원칙

1. **화면 하나 = 질문 하나.** 화면 제목이 곧 질문이다(예: "토큰이 어디에 쓰이나?"). 질문은 visualization.md 의 `question` 과 같다.
2. **숫자 먼저, 차트 다음, 근거는 클릭 한 번 뒤.** 맨 위에 답이 되는 숫자(KPI 타일), 그 아래 차트, 근거(호출 목록 · 근거 작업 · 가정)는 펼치기나 옆 패널에.
3. **강조 색은 화면당 하나.** 기본은 accent(파랑). 주황(warm)은 추정 · 긴장 신호에만 쓰고, 한 화면에 둘이 같은 뜻으로 섞이지 않게 한다.
4. **차분한 밝은 테마가 기본.** 어두운 테마는 라이브 모니터와 데스크톱 셸의 기본이다. 사용자는 어디서나 전환할 수 있다.
5. **장식 금지.** 장식용 그라데이션, 이모지, 3D 차트, 그림자 남용을 쓰지 않는다(elevation 은 1 · 2 단계만).
6. **접근성.**
   - 본문 대비는 WCAG AA 4.5:1 이상이다(`tokens.json` `contrast_pairs`, `check_docs.py` 가 계산해 검사).
   - 색은 밝기로도 구분한다. 계열은 파랑/주황이고 빨강/초록은 쓰지 않는다. 계열 사이 상대 휘도 차는 0.08 이상이다(검사).
   - 키보드로 모든 조작이 가능하고, 포커스 링은 `focus` 토큰을 쓴다.
7. **숫자는 tabular numerals.** 모든 숫자에 `font-variant-numeric: tabular-nums` 를 쓰고, 단위는 숫자 뒤에 작게 붙인다.
8. **움직임 줄이기 설정을 지킨다**(`prefers-reduced-motion`). 분석 화면의 전환은 200 ms 이하이고, 모니터는 `design/motion.md` 7 을 따른다.

## 2. 토큰

- 원본: `design/tokens.json` (design 소유). frontend 는 빌드 때 이것으로 CSS 변수(`--gc-color-text` 등)와 ECharts 테마를 만든다. 다른 곳에 색 · 크기 · 시간을 직접 쓰지 않는다.
- 글꼴: **IBM Plex Sans KR**(한글 · 라틴) + **IBM Plex Mono**(숫자 · 코드 · 모니터 단어). 둘 다 OFL 이고 self-host 한다(ADR-0009).
- 크기 단계: 12 · 14 · 16 · 20 · 24 · 28(제목) · 32(KPI). 간격은 4 의 배수, 모서리는 4 · 8 · 12, 그림자는 0 · 1 · 2.

## 3. 데이터 상태 표기 (모든 화면 공통)

| 출처 | 칩 | 선 | 범위 |
|---|---|---|---|
| MEASURED | 꽉 찬 칩 `측정` | 실선 | — |
| CALCULATED | 테두리 칩 `계산` | 실선 | — |
| ESTIMATED | 파선 칩 `추정` | 파선 | P10–P90 띠 + P50 표시 |
| SIMULATED | 점선 칩 `가정` | 점선 | P10–P90 띠 + P50 표시, 가정 목록 항상 노출 |

- 칩은 색이 아니라 **선 모양**으로 구분한다(같은 중립색). visualization.md 의 출처 표와 같은 규칙이다.
- 비용은 항상 두 기준을 **나란히** 둔다: `API 정가 환산` | `CLI 비용`. CLI 커버리지가 100 % 미만이면 `부분 n%` 를 붙인다. 모르는 값은 `—` 이다.

## 4. 배치

- 왼쪽 내비게이션(232 px)은 세 묶음이다.
  - **사용 현황:** 개요, 토큰 구성, 호출 크기, 예산 소진
  - **실행:** 라이브 모니터, (나중) 노드 타임라인 · 작업 흐름 · 동료 네트워크 · 판정 결과
  - **컨설팅:** 구성 비교, 절약 진단, 견적, What-if, 프로필
  - 아래쪽: 업로드, 알림, 감사 로그, 설정
- 본문 최대 폭은 1200 px 이고 가운데 정렬한다. 위에서부터 질문 제목, KPI 줄, 차트, 근거 순서다.
- 폰 폭(< 640 px)에서는 내비가 아래 탭 막대가 되고, KPI 는 2 열, 차트는 전체 폭에 가로 스크롤 없이 놓는다. 라이브 모니터는 무대를 다시 축척한다.
- 라이브 모니터는 예외다. 내비를 접은 전체 화면 무대 하나(어두운 테마)이고, 그 위에 조작 UI 는 재생 스크러버(마우스를 올릴 때만 보임)와 테마 · 움직임 줄이기 스위치뿐이다.

## 5. 공유 컴포넌트 (roadmap CMD-FE1)

| 컴포넌트 | 용도 | 규칙 |
|---|---|---|
| `KpiTile` | 답 숫자 | 값(32 px, tabular) + 단위 + 출처 칩 + 직전 기간 대비(작게) |
| `StatusChip` | 출처 · 상태 | 3 절 선 모양, 텍스트 12 px |
| `RangeBand` | P10–P90 띠 + P50 | ESTIMATED 는 파선, SIMULATED 는 점선 |
| `CostPair` | 두 기준 비용 | 정가 · CLI 를 같은 줄에, 커버리지 칩 |
| `BarList` | 순위 막대(모델별 · 규칙별 절감) | 막대 + 숫자, 정렬 고정 |
| `FigureCard` | (분석 화면용) 노드 요약 카드 | 모니터의 figure 모양 · 상태를 정적으로 |
| `KanbanColumn` | (분석 화면용) 작업 칸 | 대기 · 실행 · 판정 · 완료/실패 |
| `EvidenceDrawer` | 근거 펼침 | 근거 호출 · 작업 · 가정 목록 |

## 6. 라이브 모니터의 시각 언어 (요약)

모니터는 **움직이는 장면 하나**다(사양 3.1.1). 노드 · 큐 · 토큰 같은 말 대신 모양과 움직임으로 읽힌다.

| 데이터 | 장면에서 |
|---|---|
| 노드(역할) | **figure** — 역할마다 다른 모양 |
| 작업 항목 | **tile** — 위 대기 선반 → figure 손 → 아래 완료 선반 / 옆 실패 선반 |
| 턴 실행 중 | figure 안 미세 입자 + 경과에 따라 빨라지는 숨(build) |
| 동료 메시지 | 두 figure 사이 곡선을 따라 가는 빛 펄스(talk) |
| π | 선 굵기 + 거리(가까울수록 강함) |
| 동료 대기 | 흐려짐 + 기다리는 상대에게 뻗은 팽팽한 줄(wait) |
| 판정 · 결과 | figure 둘레 고리의 모양(닫힘 = 통과, 톱니 틈 = 실패, 열림 = 판단 필요, 평평한 끝 = 예산) |
| 토큰 · 비용 | figure 의 연료 호(arc), 전체는 수평선 높이(예산 대비) |
| 분위기 | 속도(입자 · 쓸기 템포), 막힘(전체 감속 · 어두워짐), 협업(모임 · 동기화), 긴장(빠른 맥박 · 수평선 따뜻한 빛 · 눈금), 완료(정렬 · 한 번의 빛) |

신호 하나하나의 대응은 `design/encoding.json` 에 있다. L0 이벤트 종류마다 하나씩이고, `check_docs.py` 가 빠짐없는지 검사한다. 숫자는 마우스를 올리거나 눌렀을 때만 작은 툴팁으로 보인다.
